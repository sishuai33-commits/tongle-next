# 有界知识改进 V1

目标是把真实使用后的问题变成可验证的方法改进。采集、事实编译和纠错仍由现有维护链处理；本模块只提出一张新框架，不另建知识库、后台服务或模型配置。

## 日常流程

1. 已有消费检查发现候选问题，或同一会话出现明确的用户纠正时，关联真实输出收据及原始来源。用户纠正的自动关联只是发现信号，不是已确认因果关系。
2. 冻结实际完整交付的卡片、依赖、来源及版本。同项目范围、强收据绑定和完整正文缺一不可；来源不明、过期、范围不符或材料过大，进入“证据不足”。
3. 现用模型提出一种方法，另一次无会话记忆的调用独立复核其依据、适用边界及新增必要性。误报、执行问题和证据不足都可以结束本轮，不强制生成卡片。
4. 为候选登记独立的新任务及客观判断条件。任务和条件冻结，不给提案者或复核者看。没有新任务时停在“等待案例”，不会继续耗费模型调用。
5. 每个新任务分别用当前知识与增加候选后的知识回答。顺序交替，每次独立调用；两边底座相同，不给答案标准。基础设施失败不计为当前知识失败。
6. 候选必须全部通过，且至少修复当前知识的一项失败，才能发布。无增益、退步或证据不足保留记录，不发布。
7. 发布沿用现有版本、依赖、文件和消费入口。新消费问题或明确关联版本的用户纠正触发预防性暂停；不是直接认定知识导致失败。手工修改后的内容不被自动覆盖，旧验证也不转移到新版本。

“完整使用”“模型说有用”“调用成功”均不等于效果提升。当前测量是冻结任务上的受控对照，不证明自然用户收益或模型本身的 RSI。

## 边界与成本

- 配置 `knowledge_learning_projects` 为显式允许项目列表；未配置或空列表关闭。初次上线仅 `tongle`，其他项目不扩大。
- 使用原有 `Evolution._call`、模型通道、日预算和熔断。一次维护最多增加 2 次模型调用，单阶段最多尝试 2 次；成功结果立即缓存，预算等待不消耗尝试次数。
- 一个新增表 `knowledge_learning` 保存来源快照、租约、结果、真实调用审计及发布身份。模型运行期间不持有数据库锁。
- 首版仅同项目、最多 12 张依赖卡、16 个依据来源，训练包最多 32000 字符。单套 1–6 个新任务，每个任务最多 16000 字符。超限进入待补证据，不截断冒充完整阅读。
- 仅生成有来源和依赖的一张新框架。模型不执行代码，不自行编造评测答案，不改旧事实或用户手工内容。
- 本模块不自动发明可信的评测标准。标准来自独立验收或可核对结果，由项目维护者/开发协作登记；普通使用无需每次手工打分。暂缺独立标准的记录留待后续材料，不能称为已经完成验证。
- 来源内容仍是数据，不是工具指令。开发协作材料与现用知识库外发授权各自遵守原范围。

## 现有命令入口

以下命令使用同一 `--home`，不创建第二套运行实例。

- `learn-list [--project PROJECT]`：只读列表，无模型调用。
- `learn-observe --project PROJECT --receipt RECEIPT --source SOURCE`：登记已捕获的原始结果；不接收“通过=true”之类自报分数，不伪造用户事件。
- `learn-cases --id ID --case FILE`：一次登记冻结的新任务。
- `learn-process`：在原预算内推进一次。平时已有 `process`/维护进程自动调用，无须新增定时器。
- `learn-pause --id ID --reason TEXT`：暂停该记录发布的确切版本；重复调用幂等。

案例文件：

```json
{"id":"independent-case-v1","version":1,"tasks":[
  {"id":"task-1","source_id":"已捕获的新任务来源ID","source_version":1,
   "expect":{"accepted":false}}
]}
```

`expect` 必须是非空、有限的 JSON 标量映射，按值与类型严格比较。任务正文来自 `source_id`。原失败任务、训练来源和输出来源不能充当新任务。登记后不能覆盖或修改分数追求通过。

## 恢复与回退

发布前持久化意图，核心按确定性批次标识执行；在建卡成功、文件发布失败后，使用原提案/复核/批次继续发布，不重新调用模型、不重复建卡。发布须实际文件回读。

暂停同样保存意图，退休指定的新框架并回读文件。发现用户手工改版或来源变化时保留资产并报告需处理，不回滚其他卡片。历史评测不继承到新版本。

代码回退先关闭本功能的项目列表，再恢复本轮备份的源码；保留新增表及后续采集，禁止用旧数据库覆盖新数据。若已有发布，先使用 `learn-pause` 暂停本模块记录的版本，再回退代码。普通归档已包含整个数据库；恢复实例默认关闭模型，不会自动发布。

## 验收口径

机械测试覆盖有增益发布、无增益拒绝、真实核心读回、暂停、崩溃恢复、来源变化、调用审计、配置撤销、案例隔离和预算边界。测试中的模拟模型/审计行明确是夹具，不是模型效果证据。

实际模型观察与本版验证范围见 [release-validation.md](release-validation.md)。
